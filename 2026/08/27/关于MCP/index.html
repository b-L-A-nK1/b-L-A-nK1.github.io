关于MCP

发表于2026-08-27|更新于2026-08-27
|浏览量:

MCP（Model Context Protocol，模型上下文协议），旨在为LLM与其它外部工具、数据源、服务等之间建立安全统一的双向连接。MCP可以让不同的AI模型能够以一致的方式接入任意外部能力，不用为每对”模型-工具”组合单独开发适配的代码

架构 Host-Client-Server三次模型

1、MCP Host(主机)

Host时运行LLM的宿主应用程序，例如Claude Desktop、Cursor IDE等等，其作用：

2、MCO Client(客户端)

Client时Host内部的协议连接组件，和MCP Server保持一对一的逻辑连接，对于每一个Client实例都封装了：

一个Host可以同时运行多个Client，但是每个Client只可连接一个Server，这样可以保证故障隔离、某个Server的崩溃不会影响到其他Server的可用性

3、MCP Server(服务器)

Server是提供能力的，以轻量级进程或者远程服务的形式存在，负责将特定功能(例如工具调用、资源访问、提示模板)封装并通过标准化接口暴露给Client

核心原语(Primitives)

MCP Server通过三种核心原语向Client暴露能力，行为上解释分别由执行、读取、模板三种交互模式

1、Tools，可执行的操作

2、Resources，可读取的数据

3、Prompts，可复用的交互模板

1、消息格式：JSON-RPC 2.0

MCP所有的通信均基于JSON-RPC 2.0 协议，消息一般分为三类

2、传输层机制

Stdio(标准输入/输出)，本地通信
Streamable HTTP，远程通信(当前标准)

SSE(Server-Sent Events)，已废弃

完整交互流程

以向Host提问某地天气如何为例

在所有流程之前会有一个前置准备阶段

初始化完成之后，Client会主动查询Server提供了哪些能力

Client会调用tools/list、resources/list、prompts/list等方法，获取Server当前可以使用的工具、资源和提示词列表

Server会根据Client的调用内容去返回相应内容的工具元数据

Host会将这些工具描述注入到LLM的系统提示词中，让模型知道自己有哪些工具可以用

动态更新：若Server后续新增或者移除了某些工具，会通过notifications/tools/list_changed通知Client刷新工具列表

来到阶段

Host接收到用户请求后，将用户问题连同可用工具的描述信息一起传给LLM

LLM会基于上下文和可用能力列表进行推理，决定使用哪个工具

LLM生成结构化的调用指令(JSON格式)，包含工具名和参数

Client将LLM的调用意图转换为标准的tools/call JSON-RPC请求，发送给对应的MCP Server

Server接收请求后会执行具体操作

Server将结果封装为结构化格式返回

如果执行失败，则会返回isError: true 以及错误信息，而不是抛出异常

Client将Server返回的结构化结果整合进模型的上下文

LLM基于工具返回的数据，用自然语言回答

通过Host将回答展示给用户

高级交互机制

1、Sampling(采样)，反向请求

MCP支持双向通信：Server可以通过sampling/createMessage请求，反向让Host的LLM进行生成，实现了Server在复杂工作流中借用模型推理能力的场景，但是需要用户批准

2、Elicitation(信息请求)

允许Server在交互过程中向用户请求补充信息例如当工具参数不完整时，Server可以直接询问用户

3、Roots(根声明)

Client可以声明URI边界，界定Server可操作的资源范围，实现最小权限原则
